Designing a fully functional, GUI-like Terminal User Interface (TUI) that feels as premium and feature-rich as desktop apps like AmneziaVPN or NordVPN requires a meticulous architecture. Terminal environments are fundamentally text grids; to achieve "Liquid Glass" inspired polish, hover effects, and seamless cross-platform TUN routing, we must deeply manipulate terminal emulators using high-performance Rust crates.
Here is the comprehensive, deeply researched blueprint for implementing the ZeroNet TUI.
1. Core Architecture & Tech Stack
To ensure extreme efficiency, memory safety, and cross-platform consistency across Linux, Windows, and macOS, the app must be divided into a headless networking daemon and an interactive rendering loop.
 * TUI Framework: ratatui paired with the crossterm backend. Ratatui provides the widget system (lists, charts, popups), while Crossterm provides raw cross-platform terminal manipulation.
 * Networking / TUN Engine: tun-rs. This is a production-ready crate that supports up to 70.6 Gbps throughput using asynchronous hardware offloading. It natively handles Windows (via wintun.dll), macOS (native feth pairs), and Linux (TUN module) seamlessly.
 * Database: rusqlite (SQLite). For saving subscriptions, configs, routing rules, and metrics, a local SQLite database ensures zero-corruption persistence even if the terminal is forcefully closed.
 * Async Runtime: tokio. The UI rendering will run on the main thread, while tokio will handle the concurrent IP scanner, Zray-Core execution, and database queries in the background.
2. Implementing GUI-Like Mouse & Hover Mechanics
Terminal apps usually rely on keyboard navigation, but Crossterm allows us to capture raw mouse data to create an app-like experience.
 * Mouse Capture: At startup, execute crossterm::terminal::enable_raw_mode() and crossterm::execute!(stdout, EnableMouseCapture). This forces the terminal to report mouse coordinates (x, y) and events (Hover, Click, Scroll) to the application loop.
 * The Intersection Engine (Hover Effects): Ratatui draws UI elements inside Rect (rectangular areas). You must write an intersection system: every tick, check if the mouse (x, y) coordinates fall within the Rect of a button or list item.
 * Visual Feedback: If the mouse hovers over a server in the config list, dynamically swap its Style (e.g., change the background from standard black to a subtle charcoal, and the text to the "Golden Dark" amber).
 * Wobbly Connect Button Illusion: While actual liquid shaders are impossible in a TUI, you can simulate motion using Ratatui's Canvas widget. Build the "Connect" button using Braille characters. On hover, apply a sine-wave function to the coordinates of the Braille dots, creating a rippling, wobbly ASCII animation at 60 FPS.
3. Cross-Platform TUN Mode Implementation
System-wide routing via TUN interfaces requires navigating strict OS-level permissions. The TUI must guide the user safely through these privilege elevations.
 * Linux Setup: The tun-rs crate will utilize the Linux kernel's tun module. The TUI must check if it has CAP_NET_ADMIN capabilities. If not, it should render a bold red popup prompting the user to run the app via sudo.
 * Windows Setup: Windows requires the wintun.dll driver. The TUI startup sequence must verify the presence of this DLL in the binary's directory. If missing, the app should automatically fetch it. It will also prompt for UAC (Administrator) elevation.
 * macOS Setup: macOS utilizes native interfaces, but still requires sudo.
 * Routing Rules Teardown: A critical failure in many VPNs is leaving dead routing rules if the app crashes, killing the user's internet. You must implement a Drop trait or a panic handler that catches unexpected exits and forces tun-rs to destroy the virtual interface and restore the default gateway.
4. Database & State Management
A VPN client requires robust state management for configurations.
 * Database Schema:
   * configs: Stores Vmess, Vless, Trojan, and Shadowsocks JSON data.
   * subscriptions: Stores URLs and auto-update intervals.
   * metrics: Logs latency history for each node to feed the UI charts.
 * Real-time Config Hot-Swapping: When a user clicks a new server in the TUI, the SQLite database updates the active_profile flag. A Tokio channel sends an Event::SwitchNode message to the background Zray-Core daemon, which drops the current TCP stream and instantly dials the new node without restarting the entire TUN interface.
5. UI Layout & The "Golden Dark" Aesthetic
Ratatui allows for complex, responsive flexbox-like layouts using Layout::split.
 * Left Sidebar (Navigation): A vertical list containing icons for "Dashboard", "Subscriptions", "IP Scanner", and "Settings". Hovering over an item highlights it with a golden left-border.
 * Main Dashboard:
   * Top Bar: Displays current IP, upload/download speeds, and active TUN status.
   * Center: The interactive Connect button. When active, a pulsing ASCII ring surrounds it.
   * Bottom: A Chart widget mapping ping latency over the last 60 seconds using green and gold Braille data points.
 * Modals & Popups: If the user presses Ctrl+A to add a config, render a centered Clear widget (which erases the UI behind it) to simulate depth, overlaid with a Block containing an input prompt for pasting clipboard data.
6. Advanced Zray-Core Integration 
The TUI must expose the advanced DPI-circumvention features seamlessly without overwhelming beginners.
 * Simple Mode: The user only sees a list of countries and a big connect button. The backend automatically applies random TCP padding, SNI fragmentation, and Cloudflare IP rotation.
 * Advanced Mode Popup: Clicking a "Gear" icon reveals low-level toggles built using Ratatui checkboxes.
   * TLS Fragment Size: Sliders to adjust the byte length of shredded initial packets.
   * Jitter Delay: Inputs to set random micro-delays between packet fragments.
   * Scanner Concurrency: Allow power users to set the background Rust IP scanner to probe 100 or 1,000 IPs simultaneously depending on their CPU thread count.
Critique & Refinement Note: The primary limitation of a TUI is typography. Terminal emulators rely on system monospace fonts, meaning custom branding fonts (like Persian Lalezar) will not render. You must design the TUI assuming standard monospace English/ASCII, utilizing Ratatui's extensive color palettes and UTF-8 block characters to create the visual identity rather than relying on typography.
